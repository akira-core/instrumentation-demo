階梯模型

優先序（先有意見者勝出）：
  relay  >  env  >  option (WithTracingEnabled)  >  hardcoded default

合成：
  tracing = master && moduleTracing

  master  : relay key otel-instrumentation-go-tracing
            | OTEL_INSTRUMENTATION_GO_TRACING_ENABLED
            | default true（否決開關，truthy 不會「打開」任何模組）
  module  : relay key otel-nats-tracing
            | OTEL_NATS_TRACING_ENABLED
            | WithTracingEnabled
            | default false

OpenFeature domain：otel-instrumentation-go
（named provider；只裝 default slot 不算 library relay）

叢集基準設定（option C）

Live 測試期間 deployment/backend 環境（只改 ConfigMap、不重啟 backend）：

PORT=8080
NATS_URL=nats://nats:4222
OTEL_EXPORTER_OTLP_ENDPOINT=http://rotel:4318
OTEL_SERVICE_NAME=demo-backend
CORS_ALLOWED_ORIGIN=*
OTEL_INSTRUMENTATION_GO_TRACING_ENABLED=1
OTEL_NATS_TRACING_ENABLED=false
OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT=http://relay-proxy:1031
OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL=2s

每個 case 都是輪詢到條件成立（或用盡重試）才記錄，不是固定 sleep。C2 額外查「本次探測開始之後」全叢集的 demo.trace span 數（每次嘗試各自取一個 ClickHouse 端時間點），用來區分「tracing 被關掉」與「propagation 壞掉、span 跑到別條 trace」。
