otel-nats feature-flag 閘門延遲
效能證據報告

評估「有開 feature flag（每 call 評估閘門）」相對於「完全不使用 feature flag / env」 在大量 Publish 需要送 trace 時，單次 call 平均 response time 的差異。 量級：N = 100, 1000, 10000, 100000。

量測方法
每模式：warmup 200 次 Publish 後，對 N∈{100,1e3,1e4,1e5} 逐次計時 conn.Publish(ctx, subject, payload)。payload 固定 ~32B。TracerProvider 使用 AlwaysSample + 記憶體 SpanRecorder（不走網路 OTLP）。比較重點：flag_on（每 call OpenFeature）vs env_on_no_flag（有 span 無 OF）vs no_flag_no_env（零閘門）。

主機：darwin/arm64 · go1.26.5 · 14 CPU · payload 30 bytes · library：otel-nats + otel-flags (workspace submodule)
解讀重點
  • no_flag_no_env：零 OpenFeature、不發 span — 下限基準。
  • env_on_no_flag：有 span、無 OF — 「需要送 trace」但不走 feature flag 的基準。
  • flag_on：每 call 評估 OF 且發 span — 本 demo option C + relay 啟用路徑。
  • flag_off：每 call 仍評估 OF，但不發 span — 閘門本身開銷。
  • 關鍵比值：flag_on / env_on_no_flag = 在同樣要送 trace 時，加上 feature-flag 閘門的倍數成本。

各模式逐步設定與證據

no_flag_no_env 完全不使用 feature flag / env（零閘門）

不綁 named provider、不設 OTEL_* 旗標變數。RelayPossible=false，模組預設 off，熱路徑不做 OpenFeature 評估，也不發 span。

① 設定步驟

1. UNSET OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT
2. UNSET OTEL_INSTRUMENTATION_GO_TRACING_ENABLED
3. UNSET OTEL_NATS_TRACING_ENABLED
4. FlagDomain → NoopProvider
5. Connect 不加 WithTracingEnabled

2. UNSET OTEL_INSTRUMENTATION_GO_TRACING_ENABLED（master 預設 true）
3. SET OTEL_NATS_TRACING_ENABLED=true
4. FlagDomain → NoopProvider

1. UNSET endpoint（避免真 GOFF）
2. SET OTEL_NATS_TRACING_ENABLED=false
3. SetNamedProviderAndWait(FlagDomain) otel-nats-tracing=true
4. 先裝 provider 再 Connect

這是單機、嵌入式 NATS、記憶體 tracer 的微基準，用來比較閘門評估相對量級， 不是端到端 HTTP/OTLP 吞吐 SLA。網路 OTLP export、relay 遠端 poll 會另加延遲。
